# 스마트보안학과 길잡이

가천대학교 스마트보안학과 학생들이 함께 만드는 진로·학습 커뮤니티예요.
진로를 탐색하고, 선배 이야기와 과목 자료를 나누고, 궁금한 걸 익명으로 묻고 답할 수 있어요.

**사이트**: https://gachon-smartsec.github.io/gachon-hub/
**운영 저장소**: [gachon-smartsec/gachon-hub](https://github.com/gachon-smartsec/gachon-hub) (학생회 공용 계정)

> 학생회가 운영하는 실제 서비스예요. 기획·정책 결정·배포·운영은 직접 하고, 코드 구현에는 AI(Claude)를 활용했어요.
> 이 저장소는 포트폴리오용 사본이고, 실제 사이트는 위 운영 저장소에서 배포돼요.

## 주요 기능

| 탭 | 내용 |
|---|---|
| 진로 지도 | 보안 직무 11개와 업종 7개, 직무별 하는 일·역량·자격증·관련 과목·커리어 경로, 학과 연구실·동아리 연결 |
| 선배 이야기 | 취업·대학원·인턴 경험을 선배가 직접 올리는 익명 게시판 |
| 연구실·활동 | 학과 연구실 7곳, 동아리, 교육 프로그램, CTF, 컨퍼런스 정리 |
| 과목 가이드 | 과목별 수강 후기·필기 정리본(파일 첨부), 선배 교재 나눔 신청 |
| QnA | 익명 질문과 답변, 좋아요가 가장 많은 답변을 베스트 답변으로 표시 |

공통 기능: 에브리타임식 익명 댓글(익명1, 익명(글쓴이)), 대댓글, 좋아요, 신고, 이용 규칙 동의

## 구조

```
[학생 브라우저] ── GitHub Pages (index.html · app.js · style.css)
       │
       ├─ 구글 로그인 (학교 메일 @gachon.ac.kr만)
       │
       └─ Supabase
            ├─ PostgreSQL + RLS   글·댓글·좋아요·신고·교재 신청
            ├─ Auth               구글 OAuth
            ├─ Storage            정리본 첨부 파일 (5MB 제한)
            └─ pg_cron            개인정보 자동 파기
```

- **읽기**는 로그인 없이 누구나, **쓰기·좋아요·신고·교재 신청**은 학교 메일 로그인 후에만 할 수 있어요.
- 서버를 따로 두지 않고, 보안 규칙을 데이터베이스(`setup.sql`)에 직접 정의했어요.

## 보안 설계

**1. 익명인데 본인 글만 지울 수 있게**
- 글마다 작성자 ID를 저장하지만, 칸 단위 권한으로 작성자 칸은 **누구도 조회할 수 없게** 막았어요. 학생은 물론 관리자 화면에도 나오지 않아요.
- 삭제는 서버 함수(`delete_content`)가 "요청한 사람이 작성자인지, 관리자인지"를 검사한 뒤에만 실행해요. 화면에서 버튼을 숨기는 것만으로 막지 않아요.

**2. 익명 번호를 서버가 매김**
- 댓글을 저장할 때 서버 트리거가 글마다 익명1, 익명2 번호를 붙여요. 같은 글에서는 같은 사람이 같은 번호를 받고, 다른 글끼리는 번호가 연결되지 않아 한 사람의 활동을 추적할 수 없어요.

**3. 권한 분리**
- 학교 메일 도메인을 서버(`is_member()`)에서 다시 검사해요. 화면 검사만 우회해도 글을 쓸 수 없어요.
- 관리자는 별도 목록 테이블(`admins`)로 관리해요. 임원이 바뀌면 목록만 고치면 돼요.
- 모든 테이블에 RLS를 켜고 기본 권한을 모두 회수한 뒤, 필요한 칸만 다시 열었어요.

**4. 개인정보 최소화**
- 교재 신청 정보(이름·학번·연락처)는 신청한 본인과 관리자만 볼 수 있어요.
- 처리가 끝난 신청 정보는 `pg_cron`으로 매년 6월 30일, 12월 31일에 자동 삭제돼요.
- 첨부 파일은 무작위 이름으로 저장해 올린 사람을 알 수 없게 하고, 형식(PDF·이미지·텍스트)과 크기(5MB)를 제한했어요.
- [개인정보처리방침](https://gachon-smartsec.github.io/gachon-hub/privacy.html)과 이용 규칙을 두고, 처음 방문할 때 규칙 동의를 받아요.

**5. 입력 검증과 출력 처리**
- 길이, 링크 형식(`https://`만), 분류값을 데이터베이스 제약 조건으로 한 번 더 검사해요.
- 화면에 출력할 때 HTML 이스케이프로 XSS를 막아요.

## 고민한 점

- **Firebase 대신 Supabase**: Firebase는 파일 저장소를 쓰려면 결제 계정 등록이 필요해서, 학생회가 매년 바뀔 때 결제 정보 인수인계가 복잡해져요. 카드 등록 없이 운영할 수 있는 Supabase 무료 요금제를 골랐어요.
- **로그인 부담 줄이기**: 로그인이 귀찮으면 아무도 안 들어오니까, 읽기는 로그인 없이 열고 쓸 때만 학교 계정으로 로그인하게 했어요.
- **인수인계**: 모든 서비스를 학생회 공용 계정으로 만들고, 관리자는 SQL 한 줄로 바꿀 수 있게 했어요.
- **오래 쓸 수 있는 정보**: 모집 일정처럼 해마다 바뀌는 정보는 빼고, 매년 그대로 쓸 수 있는 내용만 넣었어요.

## 파일

| 파일 | 설명 |
|---|---|
| `index.html` | 화면 구조 |
| `style.css` | 디자인 (라이트·다크 모드) |
| `app.js` | 화면 동작, Supabase 호출, 진로·연구실·과목 데이터 |
| `config.js` | Supabase 프로젝트 주소와 공개(anon) 키 |
| `privacy.html` | 개인정보처리방침 |
| `setup.sql` | 테이블, RLS 보안 규칙, 서버 함수, 파일 저장소, 자동 삭제 설정 |

`config.js`의 anon 키는 공개돼도 되는 키예요. 데이터 접근은 `setup.sql`의 보안 규칙이 막아요.

## 기술

Supabase (PostgreSQL · RLS · Auth · Storage · pg_cron) · GitHub Pages · Google OAuth · HTML · CSS · JavaScript

## 직접 운영하기

1. Supabase 프로젝트를 만들고 SQL Editor에서 `setup.sql`을 실행해요.
2. `insert into public.admins (email) values ('관리자@gachon.ac.kr');`로 관리자를 등록해요.
3. `config.js`에 프로젝트 주소와 anon 키를 넣어요.
4. Supabase에서 Google 로그인을 켜고, 사이트 주소를 Redirect URL에 등록해요.
5. 파일을 GitHub Pages로 배포해요.
